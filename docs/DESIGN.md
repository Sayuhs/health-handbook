# 三个模块：设计定稿

这份文件记录一次结构性重构的**全部决定和理由**。它不是为了好看——是为了下一次有人（包括未来的我）问「当初为什么这么定」的时候，答案还在。

**一句话**：这个站从一个「什么都收的医学常识库」，收成一个**三模块的速查手册**。

---

## 为什么要改

重构前：8 个分类、68 条内容、5 个页面（首页 / 紧急速查 / 自测 / 搜索 / 免责）。

问题不在内容量，在**入口混乱**，以及**一整套用不上的紧急功能**：

- `quickref/` 紧急速查页 + 每页顶部的 emergency-bar + 首页的红框，全都在喊「立即拨打 120」。
- `redflags` 9 条是纯粹的急救内容。
- 「自测」页勾选症状后输出行动档位（立即 120 / 24 小时内就医 / 尽快就诊 / 可先观察）。
- 每一条内容的 frontmatter 里都嵌着 `triage:` 数据块，供上面两个功能使用。
- 每一条内容的标题下都挂着一枚 `severity` 徽章。

站主的判断是：**真到紧急情况，没有人会打开一个网页。** 这个站的用途是**巩固医学知识**——一个速查手册。紧急那一层从里到外都不该存在。

---

## 定稿：三个模块

| 模块 | URL | 内容 | 说明 |
| --- | --- | --- | --- |
| **药品速查** | `/drugs/` | 141 种药，10 张分类表 | 每种药可被搜索、有锚点。字段：通用名 / 俗名 / 主要作用 / 常见商品名 |
| **体检指标速查** | `/labs/` | 7 条 | 中国标准优先；中国确实没有的数值，保留国际数值并**标注国别** |
| **养生** | `/wellness/` | 12 条（`foods` 6 + `lifestyle` 6） | 模块页分两节：「吃什么」/「怎么生活」 |

**导航**：首页 / 药品速查 / 体检指标速查 / 养生 / 搜索。免责与许可只出现在页脚。

### 隐藏内容

`diseases`(19) + `medications`(5) = **24 条**。

- 不出现在导航里；
- 仍然构建、仍然能被站内搜索到、老 URL 仍然能打开；
- 加 `noindex`：站内找得到，但不进搜索引擎。

**为什么保留而不是删掉**：砍掉导航就够了，入口清爽和内容存留不冲突。而「保留内容但让搜索也搜不到」是最差的组合——那等于删掉，只是占着仓库。

## 删除清单

| 删什么 | 规模 |
| --- | --- |
| `content/redflags/` + `content/symptoms/` | 15 个文件 |
| `severity` 字段（含徽章） | 全站每一条 |
| `triage:` 数据块 | 58 条 |
| `quickref:` 数据块 | 若干条 |
| 「何时必须就医」类小节 | 全部条目，**直接截断，不补新结尾** |
| 顶栏 emergency-bar、首页红框、页脚急症句 | 各一处 |
| **整个自测模块** | `check/` 页、`src/client/triage.js`、词典与抽取规则计划 |
| `quickref/` 紧急速查页 | 整页 |

**内容**：68 → 53 条。

**急症提示**：全站只保留**一行**，在「免责与许可」页。理由是留一行给「偶然点进来的人」的成本是零，而删干净后如果内容被误解成能处理急症的工具，风险更高。

### 为什么症状 6 条也删

`symptoms` 那 6 条（头痛、发热、咳嗽、腹痛、眩晕、心悸）原本要保留，唯一理由是**自测需要目的地**。自测整个模块移除之后，这个理由不再成立，于是按原议删除。

## 数据与规则

### 药品数据搬进 frontmatter

141 行的表格从 markdown 表格改成 **frontmatter 里的结构化列表**，一个分类仍然是一个文件，正文（导语、注意事项）不动。

决定性理由不是好看，是**校验**：数据结构化之后，构建可以**自动拦住违规**——「主要作用」里出现 `mg` / `每日` / `一次几片` 直接报错。**「不收录剂量」这条硬规则从「靠人自觉」变成「机器兜住」。**

### 来源标注

- 全站量化数值**以中国标准为准**。
- 中国确实没有的数值（BMI 切点、腰围切点、睡眠小时数……共 12 处）**保留国际数值，但每个都标出国别**。
- **未确认的写「未确认」，不写「没有」。** 这两者不一样，站上已经因为混淆它们出过错（见下）。

### URL 与老地址

条目 URL **一律不动**（`/foods/xxx/`、`/lifestyle/xxx/` 照旧，即使它们现在归在「养生」模块下）。以下旧地址留跳转存根：

`quickref/` · `check/` · `foods/` · `lifestyle/`

## 关键取舍（这些决定都可能被质疑，理由写在这里）

**为什么不配药品图片。**
调查结论：中国大陆市场的真实药盒/药片照片覆盖 **≈ 0%**。技术上能下载的是美国 DailyMed 的包装照片，但那是**厂商提交的**，NLM 官方明说「不能保证任何条目的版权状态」，照片「需要版权所有者的书面许可」——**技术可行，法律不可用**。唯一可能有「真实照片 + 自由许可」的是 Wikimedia Commons，而本机**完全不可达**（连接超时；本机无代理）。剩下的两条路（PubChem 分子结构式、自绘剂型图标）配出来**都不是药盒照片**，对「拿着药盒认药」这件事没有帮助。
所以：**不配图，字段里也不留位置。** 不拿别的东西冒充原始诉求。
> 若将来环境能连通 Wikimedia，第一件事就是重测 Commons。

**为什么连 `severity` 徽章也删。**
它的取值是 `routine / see-doctor / urgent / emergency`——**本质就是紧急分级**，正是要清掉的东西。注意「证据强度」徽章（strong / moderate）是另一回事，它标的是可信度，**保留**。两枚徽章不要混为一谈。

**为什么删掉整个自测模块。**
它的输出模式要求系统把口语描述拆成医学上说得清的结构（部位 / 性质 / 持续时间 / 伴随因素）。这需要一份口语→术语映射词典 + 抽取规则，是整个方案里**工作量最大的一块**。而验证时发现：症状条目删掉之后，输出里「你可能想读的条目」那一层**没有目的地可指**。
站主决定不做。这是划算的——删掉它省下的时间比删掉其他任何一项都多。

**为什么药品来源要如实降级。**
`content/drugs/` 那 10 条原本标着默沙东 / MedlinePlus / WHO 三个来源，但 141 行数据实际来自站主自制的 PDF 参考表，**那三家与这批数据之间找不到任何可验证的对应关系**。全站其余内容都做过来源核验，这是唯一一处「标了来源，但来源并不支撑内容」的地方。
处理：先如实降级标注（含「作用描述未经逐条核源」），把「逐条核源」立成独立任务分批做。**需要一个诚实的状态，而不是一个漂亮的状态。**

**永久不做的事**：不给诊断、不给患病概率、不给行动档位判定。

## 现在由机器兜住的规则

这个 repo 有一条隐含原则：**能机器化的纪律，不要靠人自觉**。起因是吃过亏——`check-search.mjs` 原本只打印结果、不断言，所以搜索退化了也没人知道。

| 规则 | 在哪一层拦 | 拦什么 |
| --- | --- | --- |
| **内容体检** | `scripts/validate-content.mjs`（CI 第一道门） | 缺来源、缺日期、slug 重复、summary 超 60 字、药品通用名撞锚点、**正文 `[N]` 引用落到不存在的来源**、`verified: false` 却没写 `verification_note` |
| **剂量守卫** | 同上 | 药品的结构化字段里出现「数字+单位」或「每日 / 每次 / 一次 / 剂量 / 用法」→ 直接失败。**这是唯一一条针对「不准写什么」的规则**，因为剂量是人最容易顺手写进去、也最容易写错的东西 |
| **产物自检** | `scripts/check-built.mjs` | 该有的页面在不在、**不该有的字样有没有**（emergency-bar / 严重度徽章 / 未被替换的占位标记）、隐藏分类是否真的 noindex、急症提示是否只剩免责页那一行、药品行锚点数是否等于索引里的药品文档数、模块级共享说明有没有漏进各个分类页 |
| **搜索实测** | `scripts/check-search.mjs` | 39 个必中查询零命中即失败；每种药必须落到**具体那一行**（而不是落到整张表） |

四道都在 CI 里，顺序是**先体检 → 再构建 → 再自检 → 最后搜索**。

**为什么值得写下来**：这四条里有三条，是在这次重构过程中**先撞到漏洞、再补出规则**才有的（剂量守卫的边界是踩了两轮才收准的；引用编号校验来自一次来源对账；产物自检来自「构建成功但页面不对」）。规则的注释里写清了「为什么不能放宽」——**不然下一个人会把它当成可以商量的东西。**
