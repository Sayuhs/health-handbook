# AGENTS.md

给接手这个仓库的 AI 协作者。读完 `README.md`、`content/README.md` 和 `docs/DESIGN.md` 再看这一份。

## 这个项目是什么

一个**静态**医学科普站点，部署在 GitHub Pages 子路径 `/health-handbook/` 下。没有后端、没有数据库、没有追踪。读者是作者本人和家中长辈，用来查某种药是什么成分、某个指标什么意思、长期吃什么怎么生活。

**这个站不处理急症，也不试图处理。** 它没有分诊、没有行动档位、没有急症提示——全站关于急救的话只有一句，在「免责与许可」页上：急症请拨 120，不要在这里查。这不是功能缺失，是设计决定：真到紧急情况，没有人会打开一个网页。**不要「顺手」把急症内容加回来。**

这句话决定了所有取舍：**可读性 > 观感，正确 > 完整，沉默 > 猜测。**

## 结构：三个模块 + 一组隐藏分类

| 模块 | URL | 内容 |
| --- | --- | --- |
| 药品速查 | `/drugs/` | 10 张分类对照表，141 种药，每种药有稳定锚点、单独进搜索索引 |
| 体检指标速查 | `/labs/` | 7 条 |
| 养生 | `/wellness/` | `foods` 6 条 + `lifestyle` 6 条 |

`diseases`(19) 与 `medications`(5) 是**隐藏分类**：仍然构建、仍然进搜索索引、老 URL 仍然能打开，但不进导航，并加 `noindex`。

导航与模块定义在 `site.config.json` 和 `scripts/lib/content.mjs` 的 `MODULES` / `CATEGORIES` 里。

## 构建链

```
node scripts/validate-content.mjs   →  内容体检（CI 第一道门禁）
node scripts/build.mjs              →  渲染 + 索引 + 样式 → dist/
node scripts/check-search.mjs       →  搜索实测（有断言，零命中会退出 1）
node scripts/serve.mjs              →  本地预览（模拟 base path）
```

**没有构建框架，也不要有。** 这个 repo 曾经用 Astro，后来撤掉了：本环境无法 spawn 管道子进程，而 Astro 的构建链必经 esbuild，导致每次本地构建都要申请更高权限。现在的生成器是三个纯 JS 依赖（marked / minisearch / yaml），`node scripts/build.mjs` 一秒出结果。

**不要引入任何需要 postinstall 或原生编译的依赖。** 引入前先确认它在受限环境下能跑。

## 硬约束

1. **内容必须有可公开访问的来源。** `scripts/lib/content.mjs` 会在构建时拦截。不要为了让构建通过而放宽校验——要改就改内容。
2. **不输出诊断结论与患病概率，也不做分诊。** 没有「你可能是什么病」，没有「急不急」，没有行动档位。这不是待补充的功能，是设计底线。
3. **不收录剂量。** 药品条目的结构化字段由构建时校验扫描，出现「数字+单位」或「每日 / 每次 / 一次 / 剂量 / 用法 / 口服」这类字样直接失败。**要放宽这条规则之前，先想清楚为什么。**
4. **`tokenize` 有两份实现，必须保持一致**：`scripts/build.mjs`（建索引）与 `src/client/search-core.js`（查询）。改一边不改另一边，会出现「索引里有、搜不到」的鬼问题。
5. **所有站内链接与资源必须带 base 前缀。** 构建时由 `site.config.json` 的 `base` 统一拼接；不要在模板里手写 `/xxx`。字体路径由 `scripts/lib/assets.mjs` 在执行时重写——漏了会静默 404，字体退回系统字体，而且没人会发现。
6. **CSS 改 `src/styles/`，不要改 `dist/styles.css`**（那是合并产物，会被覆盖）。

## 内容结构里容易踩的

- **药品的对照表不在 markdown 里。** 数据在 frontmatter 的 `drugs:` 结构化列表里，正文只留一行 `<!--DRUGS_TABLE-->` 占位标记，表格由 `scripts/lib/render.mjs` 的 `drugTable()` 渲染。改药名或加药，改 frontmatter，别去改表格。
- **模块级的共享说明放 `content/_modules/<模块>.md`。** 以 `_` 开头的文件不会被当成条目。原先 10 个药品分类各自重复同一段「使用这张表要注意的」，逐字节相同——那不是内容，是重复，现在只出现一次。
- **隐藏分类也要保持合法。** 它们不进导航，但仍然构建、仍然可搜，所以校验一样严格。
- **`verified: false` 是合法状态。** 用于「来源并不真正支撑这批数据」的内容：可以留在站上，但必须同时写 `verification_note`，页面会显著标出来。**需要的是一份诚实的状态，不是一份漂亮的状态。**

## 目录约定

- `docs/DESIGN.md` —— 三个模块的设计定稿。**结构性改动的理由都记在这里**，动结构前先读。
- `docs/SOURCES.md` —— 来源查证记录，含 20 多处「名字与内容对不上」的坑。
- `docs/ATTRIBUTION.md` —— 图片归属登记。**本站目前不使用药品图片**（真实包装照片拿不到、DailyMed 的照片有版权红线、Wikimedia 在本环境不可达）。将来加图必须登记。
- `.notes/` —— 研究过程产物与取到的原始证据，**已 gitignore**，不进入公开仓库。里面有几份很详实的调查报告（药品 PDF 结构、药品图片来源可行性、中国数值来源可达性、内容截断审计、内容×来源对账）。
- `docs/` 之外不要新建笔记类目录。

## 语气

给内容定调时记住读者是谁。不写「建议您」，不写「您应该」。写「会发生什么」「这个东西通常用来做什么」。**这不是在给建议，是在陈述事实。**
