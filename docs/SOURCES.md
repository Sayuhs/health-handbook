# 来源实录：哪些能用，哪些是陷阱

这份文档记录的是**实测结果**，不是常识。每一条都是在这台机器上用 `fetch` 打过、看过状态码与页面标题之后写下来的。

意义在于：**医学来源的可信度问题，一半是「权威不权威」，另一半是「它是不是它自称的那个东西」。** 后者更危险——页面标题正常、语句通顺、只是内容完全不相干，你看不出来。

## 一、可直接使用（已实测 200，且内容与标题相符）

### 中国政府网站内检索接口

```
https://sousuo.www.gov.cn/search-gov/data?t=zhengce&q=<关键词>
```

返回 JSON。这是绕过 `nhc.gov.cn` 全站 412 拿政府原文的路子。**但它只覆盖政策类文件**——检索「幽门螺杆菌」返回 0 条。

**一条能省很多时间的规律**：**2012／2013 年的老标准是扫描件，2021／2022 年的新标准有文本层。** 同一批 WS/T 标准里，`WS/T 404.1—2012`、`WS/T 405—2012` 只有图像（抽出来不到 200 字符），而 `WS/T 404.10—2022` 能直接抽出一万字正文。**遇到老标准，先判断有没有文本层，再决定要不要花时间。**

### 三条核对纪律

1. **看 `<title>`**，不要看文件名。文件名是抓取时人起的，会撒谎。
2. **看 `FINAL_URL`**。200 但重定向回首页，等于什么也没拿到。
3. **看正文长度**。空壳页同样返回 200。抓取脚本里最好直接记录字节数。

## 四、另外几类坑

- **静默回退（最危险的一种）**：NHS 的 `/conditions/xxx/treatment/` 这类子路径会**不报错、返回 200、但内容回退到父页**。状态码正常、页面正常、只是缺了一段——没有任何信号。同类还有 `stacks.cdc.gov/view/cdc/112700` 实际返回 `113400`，内容是霍乱周报。
- **内容重复**：NHS 的 `/diagnosis/`、`/treatment/` 子路径抓回来的字节数与主页**一模一样**。多列一条不增加信息量，只增加维护成本。
- **站点改版**：NHS 已大规模迁移，旧 `/conditions/xxx/` 大量 404，新路径在 `/symptoms/`、`/tests-and-treatments/`、`/mental-health/conditions/`。**抓 NHS 必须逐条核对 `FINAL_URL`，不能只看状态码。**
- **路由陷阱（MSD 中文版）**：`/home/brain,-spinal-cord,-and-nerve-disorders/...` 这条**带逗号**的路径对部分文章会 404，真实路径族是 `brain-spinal-cord-and-nerve-disorders`（无逗号）；耳部文章在 `ear-nose-and-throat-disorders` 下。抓之前先从目录页挖真实 slug。
- **页面自标日期与 URL 里的日期不一致**：以**页面自标**为准（例如 URL 含 `20230424`、页面写 2023-04-19）。
- **检索工具本身也会坏，而且坏得像内容问题**：`web_search` 工具余额耗尽后返回 `HTTP 402 Insufficient Balance`；360 搜索失效；Baidu 触发验证码。当时唯一还能用的通道是 **Bing，而且只在「单个中文短语」查询下有效**——多词长查询会退化成一堆泛化实体页。**堆关键词反而更差**，这条值得记住。
- **本机 `pwsh` 实际是 PowerShell 5.1**：`Get-Content` 读 UTF-8 文件必须加 `-Encoding UTF8`，否则中文乱码。**中文匹配请优先用 `node` 或 ripgrep 工具**——曾经因为用 PowerShell 做中文比对，把两个其实已经通过的检查误判成失败，白查了一轮。

## 五、拿不到就是拿不到

这一节在 2026-09 那次中国标准收口之后**大幅缩短了**：原先列在这里的项，多数已经拿到中国来源（入口见第一节末那两张表）。下面是**仍然**拿不到的。

### 仍然拿不到（写「未确认」，不写数字）

- **ALT / AST 的中国参考区间**：`WS/T 404.1—2012` 与 `WS/T 405—2012` 是**扫描件、无文本层**（只能抽出不到 200 字符），本机没有 OCR。条目里已写明标准号与官方链接，数值不列。
- **中国 eGFR 估算公式**：现行指南只采用 KDIGO 2012 的定义与 CKD-EPIcr，**没有中国专用公式的推荐**。这不是「查不到」，是「不存在可引用的」。
- **甲状腺妊娠期「诊断用」参考范围**：`WS/T 404.10—2022` 明确不适用于妊娠女性；妊娠期另有学会口径，但那是**治疗目标**，不是诊断范围。
- **中国成人每日睡眠小时数**：只找到定性表述（「劳逸结合，起居有常，保证充足睡眠」），没有小时数。
- **中国膳食纤维推荐量**：CNS 的 DRIs 页面只有出版说明与购书链接，没有数值表格。
- **中国戒烟的量化建议**：《中国吸烟危害健康报告（2020 版）》的三份转载**全是定性**。
- **血红蛋白诊断界值**：NHS / MedlinePlus / NHLBI / WHO 四个来源的页面全都只讲意义、不给 g/L 切点。
- **WHO 自己的 T 值定义原文**（官网空壳、`9241208430` 与 `WHO-TRS-843` 均 404）。

### 已经补齐的（**别再照着旧结论写「未确认」**）

中国高血压分级与家庭自测界值 ／ 糖尿病 mmol/L 诊断切点 ／ LDL-C 分层目标 ／ 血尿酸与高尿酸血症诊断值 ／ TSH·FT4·FT3 参考区间（分检测系统） ／ CKD 分期 ／ BMI 与腰围切点（含中心型肥胖前期） ／ CHA₂DS₂-VASc-60。

⚠️ **把「没有」和「未确认」弄混，是这份文档最大的风险。** 项目已经因为这一点漏掉过一个现成的中国数值——反式脂肪酸上限 ≤2 g/天，膳食指南里白纸黑字写着，条目里却标着「未确认」。**查之前先看这一节。**

**这些空白是内容的一部分。** 一个写着「未确认，请以本人化验单为准」的条目，比一个填了貌似合理数字的条目安全得多。

## 六、内容 × 来源对账（2026-09 做了一次全量侦查）

对着 53 个条目做了第一轮系统对账：**350 条「条目 × 来源」引用 / 245 个去重 URL / 1829 个数值主张**。

**结论：形式上有纪律，但「每条内容都标了来源」这句承诺，当时是不成立的。**

| 类别 | 数量 | 含义 |
| --- | --- | --- |
| 命中 | 1542 | 这个数字确实出现在被引页面里 |
| **不命中** | **68** | 页面抓到了，但里面找不到这个数字 |
| 无法判定 | 142 | 来源是 403 或扫描件 PDF，**事实上无人可核** |
| 无来源可归因 | 77 | 正文有数值，但没有任何来源能对上 |

**关键判断：缺陷的性质是「引用指向错位」，不是凭空编造。** 68 处不命中里 **44 处**的数字能在**同一个条目的另一个来源**里找到——是引用编号指错了地方，不是编了个数。真正「来源与正文直接矛盾」的是少数几例。

**由此得到一条纪律**：这类错误靠人通读查不出来，而**「靠标题相关度让机器发现」也不成立**——`sleep-hygiene` 那处引错来源，「健康中国行动」与「睡眠卫生」看上去毫无违和，机器判成完全相关。**能机器化的只有一半：数值是否出现在被引页面里。** 而引用编号错位那一类，现在由构建校验（正文里每个 `[N]` 都必须落到某个来源）拦住了。

**没有任何一轮审计覆盖的三类问题**：语义曲解、口径混淆、年份错配。这份文档只衡量**可核对性**，不等于**正确性**——别把「数字在那个页面里」当成「这句话是对的」。

### 通道状态会变，别把一次实测当永久结论

- **NICE 本轮全站 403**：17 个 `nice.org.uk` URL 全部 403，换 UA、重试两次仍然失败。而本文第一节把 NICE 记作「可用，偶发 ECONNRESET，重试可成功」。**两者都对——通道状态在会话之间会变**（Wikimedia Commons 也一样：曾经返回 200，后来整域连接超时）。引用 NICE 的那些数值在 403 期间**事实上无人可核**，包括站主自己。是否为 IP 或 UA 相关**未确认**，浏览器里打开可能是正常的。
- 遇到这种情况，**不要改内容去迁就通道**——把「本轮取不到」如实记下来，写「未确认」，不要把数值删掉、也不要换别家的数字充数。

### ⚠️ 这份对账清单本身有假阳性，引用前必须复核

抽查了它点名为「最严重」的两处，**两处都不成立**：

| 它的指控 | 实测结果 |
| --- | --- |
| `chronic-hepatitis-b` 引用「《中国公民健康素养（2024年版）》第 11 条」，但「那个第 11 条在任何被列来源里都没有」 | **不成立。** 该来源就在 `sources` 第一条。实测抓取 `content_6954649.htm`，正文含「**11.艾滋病、乙肝和丙肝通过血液、性接触和母婴三种途径传播，日常生活和工作接触不会传播。**」——与条目正文逐字相符 |
| `rheumatoid-and-gout` 的「每日饮水 2000–3000 mL」没有来源 | **不成立。** 该数字确实在它标注的《高尿酸血症营养和运动指导原则（2024年版）》里，原文「**（七）足量饮水。每日饮水建议 2000mL~3000mL**，或根据自身情况适量调整。优先选用白开水，也可饮用柠檬水。」——**内容是对的，只是原来那个 URL 差一跳**（见下） |

**两次的失败模式是同一个：抓了被引 URL，在里面找不到这个数字，就判「不命中」——既没有读 label，也没有跟进附件。** 所以那 68 处只能当**待复核的线索**，不能当结论。真要动手改内容之前，每一处都要像上面这样独立复验一遍。

### 中国政府「政策文件」页的一个固定陷阱：正文在附件里

`gov.cn/zhengce/zhengceku/...content_xxxxxxx.htm` 这类页面，**很多时候只是「通知」本身**——正文只有抬头、附件清单和落款，真正的规范内容在 **几个附件 PDF** 里，页面上一条正文都没有。

`rheumatoid-and-gout` 就是这么踩的：引的是通知页，内容却在附件里。**附件直链就写在通知页的 HTML 里**，形如 `./P02024070170033xxxxxxx.pdf`（相对路径，拼上页面所在目录即可）。实测那四个附件都 200 可下载、且**都带文本层**，能抽出正文。

**纪律：引用中国政府网的「指导原则 / 规范 / 指南」之前，先确认那个 URL 里到底有没有你要的那句话。只有附件里才有的话，就引附件的直链。**
