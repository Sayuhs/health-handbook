# 内容规范

这个目录里每一条 `.md` 就是一页。**文件必须放在与其 `category` 一致的目录里**，否则构建失败。

```
content/
  drugs/          → 模块「药品速查」    10 个分类文件，141 种药
  labs/           → 模块「体检指标速查」  7 条
  foods/          → 模块「养生」（吃什么）  6 条
  lifestyle/      → 模块「养生」（怎么生活） 6 条

  diseases/       隐藏分类：常见疾病常识    19 条
  medications/    隐藏分类：用药与检查常识   5 条

  _modules/       模块级共享说明（不是条目）
```

**模块 vs 分类**：模块是导航上的一格，分类是目录。一个模块可以含多个分类（养生 = `foods` + `lifestyle`），一个分类只属于一个模块。模块的定义在 `scripts/lib/content.mjs` 的 `MODULES` 里。

**隐藏分类**：仍然构建、仍然进搜索索引、老 URL 仍然能打开，但**不进导航，并加 `noindex`**。它们的校验标准和别的分类一样严格。

**这个站不写急症。** 没有「何时必须就医」，没有分诊，没有行动档位，没有 120 提示。全站关于急救的话只有一句，在「免责与许可」页上。**不要加回来。**

## 铁律

**一、每条必须有可公开访问的来源。** 至少一条 `sources` 条目，且 `url` 必须能打开。付费墙内容（如 UpToDate）只能用于交叉核对，不能作为链接来源。**构建时校验，缺了就直接失败**，不会上线。

**二、每条必须写明两个日期。** `updated`（最后复核日期）与 `review_due`（下次复核到期）。到期后页面页脚会出现醒目提示——这不是装饰，是防止内容腐烂的闹钟。

**三、不写诊断结论，不给概率，不做分诊。** 只写「可观察的事实」与「这个东西通常是做什么用的」。所有数值切点必须写明**依据哪一套标准与版本年份**。

**四、量化数值以中国标准为准。** 优先次序：

国家卫健委 / 中国疾控中心 / 中国政府网 → 中华医学会各专业指南与国家标准（WS/T 等） → 地方卫健委公开科普 → WHO → NICE / NHS → 美国 CDC → Cochrane → NMPA 与药品说明书。

**中国标准与国际标准不一致时，不要合并、不要换算。** 以中国标准为准；中国确实没有对应标准的，才保留国际数值，并且**必须把体系标出来**（例如「不超过 25 g（NHS）」）。读者不该猜某个数字是哪来的。

**五、拿不准就写「未确认」，不许编。** 宁缺一个数字，不错一个数字。「未确认」和「没有」是两件事——本文档的下方记录了一次把这两件事弄混、结果漏掉一个现成数值的事故。

**六、不收录剂量。** 药品条目的结构化字段由构建时校验扫描，出现剂量字样直接失败。这是唯一一条**由机器而不是由人**把关的铁律，因为剂量是人最容易顺手写进去、也最容易写错的东西。

## 复核节奏：别把到期日都设成同一天

这一条不是形式主义。当内容到几十条，如果 `review_due` 全落在同一个月，你会一次性面对几十篇要复核的文档，然后放弃——**这份手册就是这样开始腐烂的**。

所以：**刻意把到期日错开**。

| 分类 | 建议周期 |
| --- | --- |
| 常见疾病 / 体检指标 / 用药与检查 | 每年 |
| 药品速查 | 每年 |
| 养生 | 每两年 |

具体月份分散开（例如按分类或按条目轮流排到全年各月）。**「常见误区」那一节值得比 `review_due` 更勤地扫一眼**——流行说法会变，而且它们传播得比指南快。

## frontmatter

### 普通条目

```yaml
---
title: 高血压                      # 必填
category: diseases                # 必填，须与所在目录一致
slug: hypertension                # 必填，URL 片段，仅小写字母/数字/连字符
summary: 一句话结论（≤60 字）        # 必填
evidence: strong                  # 必填：strong | moderate | limited | none
updated: 2026-09-24               # 必填，YYYY-MM-DD
review_due: 2027-09-24            # 必填，YYYY-MM-DD
age_group: [adult, older]         # 可选：child | adult | older | pregnant
tags: [心血管, 血压]               # 可选
sources:                          # 必填，至少 1 条
  - label: 《中国高血压防治指南》2024 年修订版
    url: https://example.org/...
    year: 2024
---
```

### 药品条目（`content/drugs/` 下的 10 个文件）

药品**不用 markdown 表格**。数据在 frontmatter 的结构化列表里，正文只留一行占位标记：

```yaml
---
title: 解热镇痛类
category: drugs
slug: analgesics
summary: 10 种常见解热镇痛药物的成分、主要作用与常见商品名对照。
evidence: moderate
updated: 2026-09-24
review_due: 2027-09-24
tags: [药物, 商品名, 解热镇痛]
verified: false                   # 可选；见下
verification_note: "……"
drugs:
  - name: 对乙酰氨基酚            # 必填，药盒上印的通用名
    aliases: ["扑热息痛"]         # 可选，俗名（药盒上不一定印、但人们这么叫）
    effect: 解热镇痛，用于发热、头痛、关节痛   # 必填
    brands: ["泰诺林", "必理通"]   # 常见商品名
sources:
  - label: ……
---
```

正文：

```markdown
<!--DRUGS_TABLE-->
```

就这一行。表格由 `scripts/lib/render.mjs` 的 `drugTable()` 渲染，每一行带一个稳定锚点（`drugAnchor(name)`），搜索命中某一种药时直接跳到那一行。**改药、加药，改 frontmatter，不要去改表格。** 通用名全站必须唯一——撞锚点会让搜索结果指错行，构建会拦下来。

正文里必须有那个标记，否则构建失败。除标记外可以写这类药材的说明文字，但**共享说明请放到 `content/_modules/drugs.md`**，不要让 10 个文件互相复制同一段话。

### `verified: false` 什么时候用

当一条内容的来源**标注了但并不真正支撑内容**时使用。它允许内容留在站上，但必须同时写 `verification_note` 说清缺的是哪一环，页面会显著标出来。

现有唯一一例：10 个药品分类的名称/作用/商品名来自作者自制的一份参考表，尚未逐条核到原始来源。「俗名」一栏更是整理结果，没有权威清单可依——所以那一栏**填得保守，不确定就空着**。

宁可难看，不可含糊。

## 一个会咬人的细节

YAML 里**值中包含「`: `」（冒号加空格）时必须用引号包起来**，否则解析直接失败，而且报错信息会指向别处（常见的是误报 slug 重复）：

```yaml
# 错：NICE 的标题里带冒号，解析器会把它当成新的键
- label: NICE NG219 Gout: diagnosis and management
# 对
- label: "NICE NG219 Gout: diagnosis and management"
```

来源名里带冒号的情况相当常见（尤其是英文指南标题），直接加引号最省事。药品名里含 `/`（如「益康唑/曲安奈德」）也建议整条加引号。

## 正文结构

没有固定四段模板了。按这一页真正要说的事组织：开头一两段解释这是什么、为什么要关心（不要写成教科书），然后是支撑这句话所需的小节，最后可以放「常见误区」。

**结尾不要写就医指引。** 一页结束在一个事实或一句提醒上就好。

「来源」由 frontmatter 自动渲染，正文里不用重复写。

---

## 写作口吻

面向普通读者，包括中老年人。允许并鼓励医学术语的括号解释。

不要写「您应该」「建议您」这种医嘱口气；写「会发生什么」「这个东西通常用来做什么」。**这不是在给建议，是在陈述事实。**

养生类条目必须标 `evidence` 等级；没有可靠证据的说法只能出现在「常见误区」里，作为被否定的对象。
